# Contributing Guidelines

## Branching

- Never push directly to `main`
- Create feature branches per phase/task
- Open a pull request for every change

## Commit Style

- Use: `feat(scope): concise summary`
- Keep commits focused and atomic

## Pull Requests

- Ensure lint/checks pass locally
- Keep PR descriptions clear: context, changes, testing done
- Request at least one teammate review

## Code Standards

- Keep modules small and focused
- Prefer clear naming over abbreviations
- Add tests alongside behavior changes
